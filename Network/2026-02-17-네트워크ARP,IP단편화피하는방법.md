# [Network] 데이터 통신의 핵심: ARP와 IP 단편화 해결 전략

## 1. ARP (Address Resolution Protocol)
네트워크에서 IP 주소(논리적 주소)를 알고 있을 때, 실제 통신에 필요한 MAC 주소(물리적 주소)를 찾아내는 프로토콜입니다.

### 1.1 동작 원리
1. **ARP Request**: "IP가 192.168.0.5인 분? MAC 주소 좀 알려주세요!"라고 네트워크 전체에 외칩니다(브로드캐스트).
2. **ARP Reply**: 해당 IP를 가진 장비가 "저예요! 제 MAC 주소는 AA:BB:CC... 입니다"라고 응답합니다(유니캐스트).
3. **ARP Table**: 알아낸 정보를 메모리에 저장하여 다음 통신 시 재사용합니다.



### 1.2 실무 포인트
- **ARP 캐시 확인**: 리눅스 터미널에서 `arp -n` 명령어로 현재 저장된 MAC 주소 목록을 볼 수 있습니다.
- **보안**: ARP 스푸핑(Spoofing) 같은 공격을 막기 위해 중요한 서버는 MAC 주소를 정적으로 고정하기도 합니다.

## 2. IP 단편화 (IP Fragmentation)
MTU(최대 전송 단위)보다 큰 패킷을 보낼 때, 패킷을 여러 개의 작은 조각으로 나누는 현상입니다.

### 2.1 왜 발생하는가?
- 일반적인 이더넷의 **MTU는 1500바이트**입니다.
- 전송하려는 데이터가 이보다 크면 네트워크 장비(라우터 등)에서 이를 쪼개서 보냅니다.
- **단점**: CPU 부하 증가, 조각 중 하나만 잃어버려도 전체 데이터 재전송 필요 등 효율이 떨어집니다.



---

## 3. IP 단편화를 피하는 방법 (핵심 전략)
실무에서는 단편화가 발생하지 않도록 미리 조절하는 것이 성능 최적화의 핵심입니다.

### 3.1 MSS (Maximum Segment Size) 조절
- **개념**: TCP 연결 시, 단편화가 일어나지 않도록 "데이터를 한 번에 이만큼만 담자"고 합의하는 최대 크기입니다.
- **공식**: `MTU(1500) - IP 헤더(20) - TCP 헤더(20) = MSS(1460바이트)`

### 3.2 PMTUD (Path MTU Discovery)
- **원리**: 경로상의 모든 구간 중 가장 작은 MTU 값을 찾아내어 그 크기에 맞춰 데이터를 보내는 기술입니다.
- **방법**: IP 헤더의 **DF(Don't Fragment) 플래그**를 1로 설정하여 보낸 뒤, 너무 크다는 에러(ICMP)가 오면 크기를 줄여가며 최적의 크기를 찾습니다.



### 3.3 점보 프레임 (Jumbo Frames) 활용
- 내부 네트워크(LAN) 환경에서 성능을 높이기 위해 MTU를 1500 이상(보통 9000)으로 키워 단편화 자체를 줄이는 방식입니다.

---

## 4. 학습 요약 (Key Takeaways)
- **ARP**는 주소창의 이름(IP)을 보고 실제 집 주소(MAC)를 찾는 과정이다.
- **IP 단편화**는 택배 상자가 너무 커서 쪼개 보내는 것과 같으며, 이는 시스템에 부담을 준다.
- **MSS 조절과 PMTUD**를 통해 처음부터 상자 크기를 맞춰 보내는 것이 엔지니어의 핵심 역량이다.
