Network Study: 전송 계층과 네트워크 보안 기초
1. 전송 계층(Transport Layer)의 존재 이유
📡 IP 프로토콜의 한계
비신뢰성: 패킷이 유실되거나 순서가 바뀌어도 IP는 이를 해결하지 않고 목적지 컴퓨터(Host)까지만 전달합니다.

식별의 한계: IP 주소는 목적지 '컴퓨터'는 찾을 수 있지만, 그 안에서 실행 중인 **'어떤 프로그램'**으로 데이터를 보내야 할지는 구분하지 못합니다.

🚪 포트(Port)의 등장
정의: 컴퓨터 내부의 애플리케이션을 식별하기 위한 논리적인 통신 창구입니다.

역할: 전송 계층은 포트 번호를 통해 데이터를 정확한 프로세스(웹 브라우저, 게임 등)에 전달합니다.

비유: IP가 아파트의 지번 주소라면, 포트는 해당 아파트의 동/호수와 같습니다.

2. 포트를 활용한 기술: NAT와 포트 포워딩
🎭 IP 마스커레이드 (NAPT/IP Masquerade)
방향: 안에서 밖으로 (Internal → External)

핵심: 여러 대의 사설 IP 기기가 **하나의 공인 IP라는 '가면(Masquerade)'**을 쓰고 인터넷에 접속하는 기술입니다.

특이점: 내부 기기들의 포트 번호가 중복되더라도, 공유기(NAT 장비)가 외부로 나갈 때 각기 다른 포트 번호를 할당하여 충돌을 방지합니다.

📍 포트 포워딩 (Port Forwarding)
방향: 밖에서 안으로 (External → Internal)

핵심: 외부에서 공인 IP의 특정 포트로 접속했을 때, 미리 지정한 내부 사설 IP의 특정 포트로 길을 연결해 주는 기술입니다.

주의사항: 외부에서 들어오는 '현관문' 역할인 외부 포트 번호는 중복될 수 없습니다.

3. ICMP: 네트워크의 알림 서비스
역할: IP 패킷 전송 중 발생하는 오류 상황을 보고합니다.

주요 타입과 코드:

Type 3 (Destination Unreachable): 수신지 도달 불가.

Code 0/1: 네트워크/호스트 문제 (길을 못 찾음).

Code 3: 포트 도달 불가 (컴퓨터는 찾았으나 서비스가 없음).

Type 11 (Time Exceeded): TTL 만료로 인한 시간 초과.

한계: ping은 ICMP를 사용하므로 호스트의 생존 여부는 알 수 있지만, 특정 **서비스(포트)**의 활성화 여부까지는 완벽히 보장하지 못합니다.

4. [핵심] 방화벽(Firewall) vs 포트(Port)
많은 입문자가 헷갈리는 부분이지만, 둘은 엄밀히 다른 층위에서 동작합니다.

구분,포트 (Port),방화벽 (Firewall)
작동 위치,OS 내 애플리케이션,네트워크 경계 (OS 또는 외부 장비)
상태 확인,ss -tnlp (Listening 상태인가?),firewall-cmd --list-all (허용인가?)
비유,가게 주인이 뒷문을 열어둔 상태,입구 보안 요원이 출입을 허가한 상태

중요: ss -tnlp에서 0.0.0.0:22로 보인다고 해서 모든 사람이 접속 가능한 것은 아닙니다. 방화벽 설정(White List)을 통해 실제 접속 가능한 IP 범위를 좁히는 것이 클라우드 보안의 핵심입니다.

5. Rocky Linux 실습 명령어 정리
🔍 상태 확인

# 1. 현재 어떤 포트가 열려(Listening) 있는지 확인
ss -tnlp

# 2. 방화벽 허용 규칙(White List) 확인
sudo firewall-cmd --list-all

방화벽 규칙 변경

# 특정 포트(예: 80/tcp) 영구 허용
sudo firewall-cmd --add-port=80/tcp --permanent

# 설정 반영 (필수)
sudo firewall-cmd --reload
