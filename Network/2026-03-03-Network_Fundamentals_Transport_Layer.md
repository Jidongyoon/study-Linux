전송 계층(Transport Layer) 및 네트워크 심화 개념 정리
본 문서는 IP 프로토콜의 한계를 극복하기 위한 전송 계층의 역할과 포트(Port), 포트 포워딩, 그리고 네트워크 진단 프로토콜인 ICMP에 대해 다룹니다.

1. IP 프로토콜의 한계와 전송 계층의 등장
IP(Internet Protocol)는 데이터 패킷을 목적지 주소(IP Address)까지 전달하는 역할을 하지만, 다음과 같은 한계가 있습니다.

비연결성 (Connectionless): 패킷을 받을 대상이 없거나 서비스가 꺼져 있어도 패킷을 전송함.

비신뢰성 (Unreliable): 패킷이 중간에 소실되거나 순서가 바뀌어도 이를 해결하지 못함.

애플리케이션 식별 불가: 패킷이 목적지 '컴퓨터'에는 도착했으나, 그 컴퓨터 안의 어떤 '프로그램(웹 브라우저, 게임, 메신저 등)'으로 가야 할지 구분하지 못함.

해결책: 전송 계층(L4)의 TCP/UDP가 포트(Port) 번호를 통해 특정 애플리케이션을 식별하고 통신의 신뢰성을 보장합니다.

2. 포트 (Port): 데이터의 최종 목적지
IP 주소가 '아파트 지번'이라면, 포트 번호는 그 아파트의 '동/호수'와 같습니다.

정의: 하나의 IP 주소 내에서 실행되고 있는 여러 프로세스(프로그램)를 구분하기 위한 식별자.

포트 번호 범위 (0 ~ 65535):

Well-known Ports (0~1023): 주요 서비스용 (HTTP: 80, HTTPS: 443, SSH: 22 등).

Registered Ports (1024~49151): 특정 용도로 등록된 포트.

Dynamic Ports (49152~65535): 클라이언트가 통신 시 임시로 할당받는 포트.

3. 포트 포워딩 (Port Forwarding)
외부 네트워크에서 내부 사설망(Private Network)에 있는 특정 서버에 접속할 수 있도록 통로를 열어주는 기술입니다.

작동 원리:

외부 클라이언트가 공유기(방화벽)의 공인 IP와 특정 포트(예: 8080)로 접속 요청.

공유기가 설정된 규칙에 따라 해당 요청을 내부 사설 IP의 특정 포트(예: 10.1.1.20:80)로 전달.

필요성: 보안상 내부 IP는 외부에서 직접 보이지 않으므로, 게이트웨이가 중간에서 '이정표' 역할을 수행해야 함.

4. ICMP (Internet Control Message Protocol)
네트워크 장치 간에 상태 메시지를 주고받으며 통신 장애를 진단하고 보고하기 위해 사용하는 프로토콜입니다.

주요 특징:

IP 패킷 전송 중 발생하는 오류를 보고함 (L3 계층에 속하지만 데이터 전달 목적이 아님).

데이터 전송의 신뢰성을 확인하는 보조 수단.

대표적인 도구:

ping (Packet InterNet Groper): 대상 호스트까지 패킷이 도달하고 돌아오는지 확인 (Echo Request/Reply).

traceroute: 패킷이 목적지까지 가는 경로(라우터들)를 하나하나 추적.

5. 핵심 요약 (Summary)
IP는 '컴퓨터'를 찾고, Port는 '프로그램'을 찾는다.

포트 포워딩은 외부의 요청을 내부의 특정 서비스로 안전하게 안내하는 문지기 역할을 한다.

ICMP는 네트워크의 건강 상태를 체크하는 진단용 메신저이다.
