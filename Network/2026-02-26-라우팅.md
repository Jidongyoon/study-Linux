Network Navigation: Routing Tables & Protocols
네트워크의 핵심은 **"어떻게 하면 목적지까지 가장 빠르고 정확하게 데이터를 보낼 것인가?"**에 있습니다. 이를 결정하는 모든 과정을 **라우팅(Routing)**이라 합니다.

1. 🗺️ 라우팅 테이블 (Routing Table)
라우터가 가진 **'이정표'**입니다. 데이터 패킷이 들어오면 라우터는 이 테이블을 보고 어디로 보낼지 결정합니다.

주요 구성 요소:

Destination (목적지): 도달하고자 하는 네트워크의 주소.

Next Hop (다음 경유지): 목적지로 가기 위해 거쳐야 할 바로 다음 라우터의 IP.

Interface (출구): 패킷을 내보낼 실제 물리적 포트 (예: eth0).

Metric (비용): 해당 경로로 갈 때 드는 '값어치' (낮을수록 좋은 길).

2. 🚦 라우팅의 분류 (Routing Classification)
길을 찾는 '방법'에 따라 크게 두 가지로 나뉩니다.

📍 정적 라우팅 (Static Routing)
정의: 관리자가 사람이 직접 수동으로 경로를 입력하는 방식.

장점: CPU 부하가 적고 보안에 유리하며 경로가 확실함.

단점: 네트워크 변화(단선 등)에 유연하게 대처 불가능. 규모가 커지면 관리가 매우 힘듦.

비유: **"무조건 이 길로만 가!"**라고 정해진 버스 노선.

🔄 동적 라우팅 (Dynamic Routing)
정의: 라우터끼리 서로 정보를 주고받으며 상황에 따라 실시간으로 경로를 수정하는 방식.

장점: 네트워크 장애 시 우회 경로를 자동으로 탐색함. 관리가 편리함.

단점: 라우터의 자원(CPU, Memory)을 소모하며 설정이 복잡함.

비유: 실시간 교통 상황을 반영하는 T-map 내비게이션.

🗣️ 3. 라우팅 프로토콜 (Routing Protocols)
라우터들이 서로 대화하는 '언어'이자 '규칙'입니다. 알고리즘에 따라 분류됩니다.

📏 거리 벡터 (Distance Vector)
방식: 인접한 라우터와만 정보를 주고받으며 '거리(Hop Count)'와 '방향'만 고려함.

대표 프로토콜: RIP (최대 15개 홉 제한).

특징: 구조가 간단하지만 수렴 속도가 느리고 대규모 네트워크에는 부적합.

🔗 링크 상태 (Link State)
방식: 네트워크 전체 지도를 직접 그리며, 모든 라우터의 상태 정보를 공유함.

대표 프로토콜: OSPF (가장 널리 쓰이는 표준).

특징: 변화에 매우 빠르게 대응하며 최단 경로 알고리즘(Dijkstra)을 사용함.

🌐 자율 시스템 간 (EGP/BGP)
대표 프로토콜: BGP.

특징: 서로 다른 조직(KT, SKT, Google 등) 간의 거대한 인터넷 연결을 담당하는 '끝판왕' 프로토콜.

🏆 4. 말로 설명하기 위한 핵심 요약 (Cheat Sheet)
"라우팅은 우체국 시스템과 같습니다."

라우팅 테이블은 우체국에 붙은 '지역별 배송 분류표'입니다.

정적 라우팅은 우편 번호를 보고 무조건 정해진 트럭에 싣는 수동 방식이고,

동적 라우팅은 도로가 막히면 알아서 다른 길로 가는 스마트 배송 시스템입니다.

OSPF나 BGP 같은 프로토콜은 전국/전 세계 우체국들이 "어느 길로 와야 제일 빠른지" 서로 무전기로 정보를 주고받는 통신 규약입니다.
