Network Foundation: IP Address & Subnetting
이 문서는 IP 주소의 구조부터 클래스풀/클래스리스 체계, 서브네팅, 그리고 공인/사설 및 정적/동적 IP의 차이점까지 네트워크 주소 체계 전반을 정리한 가이드입니다.

1. IP 주소의 구조 (Structure of IP Address)
IP 주소(IPv4)는 32비트 숫자로 구성되며, 사람이 읽기 편하도록 8비트씩 4부분(Octet)으로 나누어 점을 찍어 표기합니다. (예: 192.168.111.100)

네트워크 부분 (Network ID): 어떤 네트워크(동네)에 속해 있는가?

호스트 부분 (Host ID): 그 네트워크 내에서 어떤 컴퓨터인가?

2. 클래스풀 주소 체계 (Classful Addressing)
초기 인터넷에서 사용하던 방식으로, IP 주소를 5개의 클래스(A, B, C, D, E)로 나누어 할당하는 방식입니다.

클래스,첫 번째 옥텟 범위,기본 서브넷 마스크,용도
A 클래스,0 ~ 127,255.0.0.0 (/8),"대규모 네트워크 (국가, 대기업)"
B 클래스,128 ~ 191,255.255.0.0 (/16),"중규모 네트워크 (대학, 중견기업)"
C 클래스,192 ~ 223,255.255.255.0 (/24),"소규모 네트워크 (가정, 소기업)"
D 클래스,224 ~ 239,-,멀티캐스트 (방송용)
E 클래스,240 ~ 255,-,미래 예약 및 연구용
한계: 네트워크 크기가 고정되어 있어 IP 주소 낭비가 심하다는 단점이 있습니다.

3. 클래스리스 주소 체계와 서브네팅 (Classless & Subnetting)
클래스풀의 낭비를 막기 위해 등장한 현대적 방식입니다.

📍 CIDR (Classless Inter-Domain Routing)
클래스에 상관없이 비트 단위로 네트워크 범위를 자유롭게 지정합니다.

표기 예: 192.168.1.0/26 (앞의 26비트가 네트워크 영역임)

📍 서브네팅 (Subnetting)
하나의 큰 네트워크를 여러 개의 작은 네트워크(Subnet)로 쪼개는 과정입니다.

목적: IP 주소 절약, 브로드캐스트 도메인 분할을 통한 성능 향상, 보안 강화.

서브넷 마스크: 어디까지가 네트워크인지 1(255)로 마스킹하여 호스트 영역과 구분합니다.

4. 공인 IP vs 사설 IP (Public vs Private)
IP 주소 부족 문제를 해결하기 위해 주소의 용도를 구분했습니다.

공인 IP (Public IP):

인터넷 서비스 공급자(ISP)로부터 할당받은 전 세계에서 유일한 주소.

인터넷상에서 직접 통신이 가능함.

사설 IP (Private IP):

내부망(집, 회사) 내에서만 사용하는 주소. 외부 인터넷에서는 보이지 않음.

대역: 10.x.x.x, 172.16.x.x ~ 172.31.x.x, 192.168.x.x

NAT (Network Address Translation) 기능을 통해 사설 IP가 공인 IP로 변환되어 인터넷에 접속함.

5. 정적 IP vs 동적 IP (Static vs Dynamic)
주소를 할당하는 방식에 따른 차이입니다.

정적 IP (Static IP):

사용자가 직접 수동으로 입력하여 고정시킨 주소.

용도: 웹 서버, DNS 서버, 메일 서버 등 주소가 바뀌면 안 되는 서버 장비.

동적 IP (Dynamic IP):

DHCP 서버로부터 자동으로 빌려오는 주소. 사용 시간이 끝나면 반납하거나 갱신함.

용도: 일반 PC, 스마트폰 등 주소가 바뀌어도 큰 문제가 없는 일반 단말기.

6. 요약 및 통찰 (Summary)
클라우드 엔지니어링 관점에서 IP 주소 체계는 **VPC(Virtual Private Cloud)**를 설계할 때 가장 먼저 고려해야 할 요소입니다.

**클래스리스(CIDR)**를 통해 효율적인 범위를 산정하고,

서브네팅을 통해 공개망(Public Subnet)과 비공개망(Private Subnet)을 분리하며,

사설 IP와 NAT를 사용하여 보안과 IP 효율성을 동시에 챙기는 것이 설계의 핵심입니다.
