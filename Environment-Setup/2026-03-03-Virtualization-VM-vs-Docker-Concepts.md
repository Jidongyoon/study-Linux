[Study] 가상화 기술의 이해: VirtualBox(VM)부터 Docker(Container)까지
1. 가상화 기술(Virtualization) 개요
가상화란 물리적인 하드웨어 자원(CPU, 메모리, 저장공간 등)을 추상화하여, 하나의 물리적 서버에서 여러 개의 독립적인 운영체제나 환경을 실행하는 기술을 의미합니다.

2. Type 1: 하이퍼바이저 기반 가상화 (VirtualBox & Windows 10)
가상 머신(VM) 방식은 물리 하드웨어 위에 **하이퍼바이저(Hypervisor)**를 설치하고, 그 위에 완전히 독립된 **게스트 OS(Guest OS)**를 실행하는 방식입니다.

2.1. 특징
독립성: 각 VM은 커널을 포함한 전체 OS를 가지고 있어 보안적으로 매우 강력하게 격리됩니다.

무거움: OS 전체를 부팅해야 하므로 리소스 소비가 크고 실행 속도가 상대적으로 느립니다.

2.2. VirtualBox 내 Windows 10 설치 핵심 단계
리소스 할당: 호스트 PC의 자원(최소 RAM 4GB, CPU 2Core 이상 권장)을 분할 할당.

가상 디스크 생성: VDI(VirtualBox Disk Image) 포맷으로 가상 하드 드라이브 생성.

ISO 마운트: 윈도우 설치 이미지 파일을 가상 광학 드라이브에 삽입하여 부팅.

게스트 확장(Guest Additions) 설치: 마우스 통합, 해상도 조절, 클립보드 공유를 위해 반드시 필요한 드라이버 패키지.

3. Type 2: 컨테이너 기반 가상화 (Docker)
도커는 OS 전체를 가상화하는 것이 아니라, 호스트의 커널(Kernel)을 공유하면서 프로세스를 격리된 환경에서 실행하는 기술입니다.

3.1. VM vs Container 비교

구분,가상 머신 (VM),도커 컨테이너 (Docker)
구조,하드웨어 레벨 가상화,OS 레벨 가상화 (프로세스 격리)
운영체제,게스트 OS 포함 (매우 무거움),OS 커널 공유 (매우 가벼움)
배포 단위,가상 머신 이미지 (GB 단위),도커 이미지 (MB 단위)
시동 속도,분 단위 (OS 부팅 필요),초 단위 (프로세스 실행)

3.2. 도커의 주요 개념
이미지(Image): 애플리케이션 실행에 필요한 모든 파일과 설정(환경)을 담고 있는 읽기 전용 템플릿 (붕어빵 틀).

컨테이너(Container): 이미지를 실행한 상태. 격리된 환경에서 애플리케이션이 동작하는 실체 (붕어빵).

도커 허브(Docker Hub): 전 세계 사람들이 만들어 놓은 이미지를 공유하는 저장소.

4. 도커 운영 프로세스 (Workflow)
4.1. 이미지 확보 (Pull)
Docker Hub와 같은 저장소에서 필요한 이미지를 다운로드합니다.

docker pull [이미지명]:[태그]

4.2. 컨테이너 생성 및 실행 (Run)
이미지를 기반으로 격리된 환경을 만들고 명령어를 실행합니다.

docker run -it --name [컨테이너이름] ubuntu bash

-i (interactive): 사용자가 입력을 할 수 있는 상태 유지.

-t (tty): 터미널 환경(Bash Shell) 이용 가능하게 함.

4.3. 컨테이너 관리
목록 확인: docker ps (실행 중), docker ps -a (정지된 것 포함)

중지/시작: docker stop [ID], docker start [ID]

삭제: docker rm [ID] (컨테이너 삭제), docker rmi [Name] (이미지 삭제)

5. 결론: 왜 가상화와 도커를 배우는가?
환경 일관성: "내 컴퓨터에서는 되는데 서버에서는 안 돼요"라는 문제를 원천 차단합니다.

효율적 자원 사용: VM보다 가벼운 도커를 통해 하나의 서버에서 수십 개의 서비스를 동시에 운영할 수 있습니다.

빠른 확장성: 필요할 때 즉시 동일한 환경의 서버를 수천 대까지 복제하여 배포할 수 있습니다.
