Linux Mail Server Infrastructure: From DNS to Sendmail
이 문서는 라운드 로빈 네임서버의 개념부터 실제 네이버-다음 메일 서버 환경을 구축하는 과정과 그 흐름을 정리한 기술 문서입니다.

1. DNS 기초와 라운드 로빈 (Round Robin)
메일 서버 구축에 앞서, 부하 분산을 위한 라운드 로빈 DNS의 개념을 이해하는 것이 중요합니다.

🚩 개념
라운드 로빈: 하나의 도메인 이름에 여러 개의 IP 주소를 할당하여, 사용자가 접속할 때마다 순차적으로 IP를 반환하는 방식입니다.

장점: 고가의 장비 없이도 여러 대의 서버로 접속을 분산(부하 분산)할 수 있습니다.

🛠️ 설정 방식 (Zone 파일)

; 동일한 호스트 이름(www)에 다른 IP를 여러 개 등록
www    IN    A    192.168.111.101
www    IN    A    192.168.111.102
www    IN    A    192.168.111.103

2. 메일 서버 구현을 위한 DNS 설계
메일은 일반 웹 접속과 달리 **"이 도메인의 메일을 담당하는 서버가 누구인가?"**를 알려주는 특수한 이정표가 필요합니다.

📍 MX(Mail Exchanger) 레코드
역할: 해당 도메인(@naver.com 등)으로 오는 메일을 수신할 서버의 호스트 이름을 지정합니다.

흐름:

발신 서버가 naver.com의 MX 레코드를 조회함.

DNS가 mail.naver.com이라고 알려줌.

다시 mail.naver.com의 IP(A 레코드)를 조회하여 최종 목적지 IP를 찾아냄.

3. 샌드메일(Sendmail) 서버 구현 흐름
실제 네이버(111.100)와 다음(111.200) 서버를 가상으로 구축할 때 적용되는 아키텍처입니다.

🏗️ 주요 구성 요소
MTA (Mail Transfer Agent): 서버 간 메일을 주고받는 트럭 (예: Sendmail).

MDA (Mail Delivery Agent): 도착한 메일을 사용자의 편지함에 넣어주는 집배원 (예: Procmail).

MUA (Mail User Agent): 사용자가 메일을 읽고 쓰는 프로그램 (예: Thunderbird).

POP3/IMAP: 서버의 편지함에서 내 컴퓨터로 메일을 가져오는 프로토콜 (예: Dovecot).

🔄 메일 송수신 전체 프로세스
메일 작성: kim@naver.com이 lee@daum.net에게 메일을 씀.

SMTP 전송: 네이버 서버가 DNS에 daum.net의 MX 레코드를 물어봄.

경로 확인: DNS가 다음 서버의 IP(192.168.111.200)를 알려줌.

서버 간 통신: 네이버 서버가 다음 서버의 **25번 포트(SMTP)**로 메일을 던짐.

수신 및 보관: 다음 서버의 Sendmail이 메일을 받아 lee 사용자의 편지함(mbox)에 저장함.

메일 확인: lee 사용자가 썬더버드(MUA)를 켜서 **110번 포트(POP3)**로 접속해 메일을 가져감.

4. 실전 구축 가이드 (Naver & Daum Lab)
Step 1: DNS 서비스(BIND) 설정
각 도메인에 맞는 zone 파일을 생성하여 메일 서버의 위치를 정의합니다.

/etc/named.conf: naver.com과 daum.net 존 구역 선언.

/var/named/naver.com.db: IN MX 10 mail 및 mail IN A 192.168.111.100 등록.

Step 2: Sendmail 보안 및 릴레이 설정
외부에서 메일을 보낼 수 있도록 권한을 설정합니다.

/etc/mail/access: 메일을 보낼 수 있는 IP나 도메인을 RELAY로 허용.

makemap hash /etc/mail/access < /etc/mail/access: DB 파일로 변환.

Step 3: Dovecot 수신 서비스 설정
사용자가 메일을 가져갈 수 있도록 POP3 서비스를 개방합니다.

/etc/dovecot/dovecot.conf: 모든 IP에서 접속 가능하도록 listen = *, :: 설정.

/etc/dovecot/conf.d/10-auth.conf: 평문 로그인 허용 (disable_plaintext_auth = no).

5. 결론 및 요약
오늘의 실습은 **"이름(Domain) → 주소(IP) → 서비스(SMTP/POP3)"**로 이어지는 인프라의 핵심 연결 고리를 구축한 과정입니다.

DNS는 지도를 그리고,

Sendmail은 실제로 물건(데이터)을 배달하며,

Dovecot은 도착한 물건을 주인에게 전달하는 체계를 완성한 것입니다.
