# 💾 Linux RAID Level & Fault Tolerance 핵심 요약

오늘 실습을 통해 학습한 Linear RAID와 RAID 0, 1, 5의 구조적 차이 및 결함 허용 원리를 정리합니다.

---

## 1. RAID 레벨별 특징 비교

| RAID 레벨 | 명칭 | 특징 | 장점 | 단점 | 결함 허용 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Linear** | 이어붙이기 | 디스크를 순차적으로 연결하여 하나의 큰 용량으로 사용 | 용량 극대화 | 속도 향상 없음 | **X** (하나만 고장 나도 위험) |
| **RAID 0** | 스트라이핑 (Striping) | 데이터를 여러 디스크에 나누어 동시에 저장 | **가장 빠른 속도** | 안정성 최악 | **X** (하나만 고장 나도 전체 데이터 손실) |
| **RAID 1** | 미러링 (Mirroring) | 똑같은 데이터를 두 디스크에 동일하게 복사 | **최고의 안정성** | 용량 효율 50% 하락 | **O** (디스크 1개 고장 시에도 서비스 가능) |
| **RAID 5** | 패리티 (Parity) | 데이터와 패리티(오류 검구 정보)를 분산 저장 | 속도, 용량, 안전의 **가장 뛰어난 균형** | 디스크 최소 3개 필요 | **O** (디스크 1개 고장 시 복구 가능) |

---

## 2. 결함 허용(Fault Tolerance)과 복구 원리

### 🔍 결함 허용이란?
시스템을 구성하는 하드웨어(디스크)에 고장이 발생하더라도, 데이터 손실 없이 서비스를 중단하지 않고 계속 운영할 수 있는 능력입니다.

### 🛠️ RAID 레벨별 복구 방식
- **RAID 1 (Mirroring)**: 똑같은 복사본이 다른 디스크에 존재하므로, 고장 난 디스크를 빼고 새 디스크를 끼우면 기존 복사본을 그대로 복제하여 복구합니다.
- **RAID 5 (Parity)**: 데이터 디스크들이 고장 나도 나머지 디스크들에 분산된 '패리티' 정보를 조합하여 원래 데이터를 계산(XOR 연산)해냅니다. 새 디스크 추가 시 이 계산을 통해 데이터를 다시 채워 넣습니다.

---

## 3. 실습 핵심 명령어 레퍼런스

### 🔨 RAID 생성 및 관리
- `mdadm --create /dev/md0 --level=0 --raid-devices=2 /dev/sdb1 /dev/sdc1`
  - 새로운 RAID 어레이를 생성합니다.
- `mdadm --detail /dev/md0`
  - 특정 RAID 장치의 상세 상태(고장 여부, 멤버 디스크 등)를 확인합니다.

### 🚑 결함 허용 테스트 및 복구
1. **강제 고장 발생**: `mdadm /dev/md1 --fail /dev/sde1`
2. **고장 디스크 제거**: `mdadm /dev/md1 --remove /dev/sde1`
3. **새 디스크 추가**: `mdadm /dev/md1 --add /dev/sdf1`
4. **복구 모니터링**: `watch cat /proc/mdstat` (데이터 재구축 과정 확인)

## 4. 실습 회고
- **Linear/RAID 0**는 데이터 가용성보다는 용량과 성능에 집중된 방식임을 확인.
- **RAID 1/5**는 실제 서버 운영 환경에서 데이터 보존을 위해 필수적인 기술임을 체감.
- 복구 실습을 통해 디스크 교체 시 **신규 디스크의 초기화(`zero-superblock`)**와 **동기화 시간**의 필요성을 학습함.
