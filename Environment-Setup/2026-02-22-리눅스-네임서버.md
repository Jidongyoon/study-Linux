nux DNS(Domain Name System) 서버 완벽 가이드
1. 네임서버의 종류 및 개념도
① 캐싱 전용 네임서버 (Caching-only Name Server)
개념: 직접 관리하는 데이터는 없지만, 클라이언트의 요청을 외부 DNS에 물어보고 그 결과를 전달 및 저장하는 서버.

흐름: Client → Caching DNS → External DNS(Root/TLD) → Caching DNS(결과 저장) → Client

② 마스터 네임서버 (Master Name Server)
개념: 특정 도메인(예: thisislinux.com)에 대한 권한을 가지고 호스트 정보를 직접 배포하는 서버.

흐름: Client → Master DNS(자체 Zone 파일 조회) → Client

2. DNS 서비스 설정 파일 간의 상관관계 (Flow)
DNS 서비스는 설정 파일들이 사슬처럼 엮여서 동작합니다. 하나라도 어긋나면 서비스가 중단됩니다.

/etc/named.conf: 서버의 대문입니다. (누가 들어올지, 누구에게 대답할지 결정)

/etc/named.rfc1912.zones: 서버가 가진 장부 목록입니다. (내가 관리하는 도메인 이름 선언)

/var/named/[Zone 파일]: 실제 장부 내용입니다. (그 도메인의 실제 IP 주소 기록)

/etc/resolv.conf: 클라이언트가 길을 묻는 곳입니다. (서버의 IP 주소 등록)

3. 핵심 설정 파일 상세 분석

📝 마무리 요약
캐싱 서버는 질문을 대신 해주는 **'심부름꾼'**이다.

마스터 서버는 정답을 직접 들고 있는 **'주인'**이다.

통신이 안 될 때는 서버의 any; 설정과 **클라이언트의 resolv.conf**를 가장 먼저 확인한다.
