System Integration & Troubleshooting Report
Date: 2026-02-26

Environment: Windows 11 (Host) / VMware Workstation (Guest: Rocky Linux, Windows)

Task: Development Environment Setup (VS 2026, MariaDB, Oracle 18c XE)

🛠️ Case 1: Visual Studio & Windows Update Installation Stagnation
1. 문제 현상 (Symptom)
설치 게이지가 특정 구간(특히 마지막 단계)에서 30분 이상 멈춤.

네트워크 속도(100Mbps) 대비 데이터 수신량이 급격히 하락(kbps 단위).

시스템은 다운되지 않았으나, 노트북 팬 소음(Fan Noise)이 심해지고 전체적인 반응 속도가 저하됨.

2. 원인 파악 (Root Cause Analysis)
Resource Bottleneck: 작업 관리자 확인 결과 CPU 점유율이 95~100%에 육박.

Memory Starvation: 할당된 4GB RAM 중 82% 이상이 점유되어 '디스크 스왑(Disk Swap)' 발생.

Post-Processing (NGen): .NET Framework 설치 후 하드웨어 최적화를 위한 mscorsvw.exe (NGen) 프로세스가 CPU 자원을 독점함.

Network Throttling: 인터넷 문제가 아니라, CPU가 데이터를 처리하지 못해 수신을 거부하는 '수신 병목' 현상.

3. 문제 해결 (Resolution)
Wait & Monitor: 강제 종료 대신 시스템 유휴 상태(Idle)가 될 때까지 대기하여 백그라운드 최적화 작업 완료 유도.

Resource Optimization: 설치 완료 후 VM 설정을 변경하여 RAM을 4GB에서 8GB로, CPU 코어 수를 4개로 증설하여 I/O 대기 시간 단축.

Environmental Support: 노트북 하단을 띄워 공기 흐름을 개선함으로써 '서멀 스스로틀링(온도 상승으로 인한 성능 저하)' 방지.

🗄️ Case 2: Oracle Database 18c XE Configuration Delay
1. 문제 현상 (Symptom)
service oracle-xe-18c configure 실행 중 7% complete (Copying database files) 단계에서 장시간 정체.

2. 원인 파악 (Root Cause Analysis)
Disk I/O Intensive Task: Oracle 인스턴스 생성 과정은 단순히 파일 복사가 아니라, DB 구조물(TableSpace, Control Files)을 디스크에 물리적으로 생성하는 고부하 작업임.

Virtualization Overhead: 가상 머신의 가상 디스크(vmdk) 환경에서 실제 물리 디스크 성능을 100% 활용하지 못해 발생하는 지연.

3. 문제 해결 (Resolution)
Patience Strategy: Oracle 설치는 'Wait or Die' 단계임을 인지하고 프로세스가 완료될 때까지 터미널 유지.

Result: 최종적으로 SELECT * FROM customer 쿼리를 통해 데이터 조회 성공 및 C# 연동 확인.

⌨️ Case 3: SQL*Plus UX Inconvenience (History/Autocomplete)
1. 문제 현상 (Symptom)
리눅스 환경의 sqlplus 터미널에서 방향키 사용 시 이전 명령어 호출(History)이 안 되고 ^[[A와 같은 깨진 문자가 출력됨. 오타 수정 시 백스페이스 작동이 원활하지 않음.

2. 원인 파악 (Root Cause Analysis)
Oracle 기본 sqlplus 도구는 현대적인 입력 라이브러리(GNU Readline)를 지원하지 않는 레거시 인터페이스를 사용함.

3. 문제 해결 (Resolution)
Tool Injection: rlwrap (Readline Wrapper) 설치 및 적용.

Automation: .bashrc 파일에 별칭(Alias)을 등록하여 사용성 개선.

Effect: 방향키를 이용한 쿼리 히스토리 탐색 및 자동완성 기능 활성화로 개발 생산성 향상.

💡 Lessons Learned
모니터링의 중요성: 게이지가 멈췄을 때 작업 관리자의 CPU/Memory 지표를 확인하여 '다운'인지 '작업 중'인지 판단하는 역량이 필수적임.

사양 할당의 미학: 무거운 Enterprise 소프트웨어(VS, Oracle)를 다룰 때는 최소 사양보다 권장 사양(RAM 8GB 이상)을 할당하는 것이 전체 작업 시간을 단축시킴.

도구의 활용: 불편함을 감수하기보다 rlwrap 같은 래퍼 도구나 GUI(DBeaver)를 적극 도입하여 실무 효율을 높여야 함.
