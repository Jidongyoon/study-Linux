TroubleShooting: MariaDB Remote Connection & PowerShell Environment
1. 개요 (Context)
목적: Windows 11 클라이언트 VM에서 Rocky 서버의 MariaDB에 원격 접속 시도

환경:

Server: Rocky (IP: 192.168.111.100), MariaDB 10.x

Client: Windows 11, MariaDB 10.9 Client, PowerShell

2. 문제 상황 (Problem)
이슈 1: 명령어 인식 불가 (CommandNotFoundException)
파워쉘에서 mysql 명령어를 입력했을 때, 빨간색 에러 메시지와 함께 명령어를 인식하지 못함.

Error Message: mysql : 'mysql' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는 프로그램 이름으로 인식되지 않습니다.

이슈 2: 원격 서버 접속 거부 (Connection Error)
정확한 경로에서 명령어를 실행했음에도 서버에 연결할 수 없음.

Error Message: ERROR 2002 (HY000): Can't connect to server on '192.168.111.100' (10061)

3. 원인 분석 (Root Cause Analysis)
경로 미지정 (Path Issue): MariaDB 설치 폴더(bin)가 윈도우 환경 변수(Path)에 등록되지 않아, 해당 폴더 밖에서는 mysql.exe를 찾을 수 없음.

파워쉘 보안 정책: 파워쉘은 현재 디렉토리에 있는 실행 파일이라도 보안상 ./를 붙이거나 절대 경로를 명시해야 실행 가능함.

네트워크/방화벽 차단: 리눅스 서버의 MariaDB 서비스가 꺼져 있거나, 3306 포트가 방화벽에 의해 막혀 있음.

DB 권한 부재: DB 내부 유저에게 외부 접속(%) 권한이 부여되지 않음.

4. 해결 방법 (Resolution)
단계 1: 절대 경로 및 호출 연산자(&) 사용
파워쉘에서 공백이 포함된 경로를 실행하기 위해 호출 연산자(&)와 따옴표를 사용하여 직접 실행함.

& "C:\Program Files\MariaDB 10.9\bin\mysql.exe" -h 192.168.111.100 -u winuser -p

단계 2: 리눅스 서버 방화벽 및 서비스 점검

# 1. MariaDB 서비스 상태 확인 및 재시작
systemctl restart mariadb

# 2. 방화벽 3306 포트 허용
firewall-cmd --add-service=mysql --permanent
firewall-cmd --reload

단계 3: DB 외부 접속 권한 부여

-- MariaDB 내부에서 실행
GRANT ALL PRIVILEGES ON *.* TO 'winuser'@'%' IDENTIFIED BY 'password';
FLUSH PRIVILEGES;

5. 결과 (Result)
정상 접속 확인: MariaDB [(none)]> 프롬프트 확인.

데이터 검증: customer, purchase 테이블 생성 및 데이터 입력(INSERT) 후 SELECT 쿼리 결과 확인 완료.

6. 교훈 및 기본기 (Lessons Learned)
터미널의 특성: 터미널은 라인 단위로 명령을 전송하므로, 엔터를 친 이전 줄로 돌아가 수정할 수 없다. 오타 발생 시 \c로 취소하거나 다음 줄에서 문법을 보완해야 한다.

환경 변수의 중요성: 자주 쓰는 도구는 시스템 환경 변수(Path)에 등록해야 생산성이 향상된다.

절대 경로 vs 상대 경로: 실행 위치에 구애받지 않으려면 전체 경로(Absolute Path)를 사용하는 것이 가장 확실하다.

"윈도우 11의 낯설음 (OS UI 이슈)"
상황: 키보드의 ₩ 버튼을 눌렀는데 화면에는 \(역슬래시)가 나와서 입력이 제대로 되고 있는지 혼란이 옴.

해결: 한국어 윈도우 폰트의 특성일 뿐, 컴퓨터는 동일하게 인식한다는 것을 이해함.
