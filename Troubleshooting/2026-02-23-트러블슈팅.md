[Troubleshooting] Linux Mail Server (SMTP/POP3) & DNS Configuration
오늘 실습하며 발생한 주요 이슈와 해결 과정, 그리고 핵심 개념을 정리한 리포트입니다.

1. 개요 (Infrastructure Overview)
환경: VMware Workstation (Rocky Linux)

도메인: naver.com, daum.net

사용 서비스:

BIND: DNS 네임서버 설정 (Port 53)

Sendmail: SMTP 메일 송신 서버 (Port 25)

Dovecot: POP3 메일 수신 서버 (Port 110)

Thunderbird: 메일 클라이언트 연동

2. 주요 트러블슈팅 내역
🔍 Issue 1: DNS MX/A 레코드 불일치 및 오타
현상: named-checkzone 실행 시 has no address records (A or AAAA) 경고 발생 및 nslookup 결과 IP가 업데이트되지 않음.

원인 분석:

FQDN 마침표(.) 누락: DNS 설정 파일(zone 파일)에서 전체 도메인 뒤에 마침표를 찍지 않아 mail.naver.com.naver.com 처럼 중복 합성됨.

Serial 번호 미갱신: Zone 파일을 수정했으나 Serial 번호를 올리지 않아 네임서버가 변경 사항을 무시함.

해결 방법:

; 수정 전
IN MX 10 mail.naver.com
mail IN A 192.168.111.100

; 수정 후 (끝에 마침표 추가 또는 호스트명만 사용)
IN MX 10 mail.naver.com.
mail IN A 192.168.111.200

수정 후 systemctl restart named로 서비스 재시작 필수.

 Issue 2: 브라우저 접속 불가 (NXDOMAIN)
현상: 웹 브라우저에서 cafe.naver.com 접속 시 DNS_PROBE_FINISHED_NXDOMAIN 에러 발생.

원인 분석:

DNS 레코드 누락: 네임서버 명부(naver.com.db)에 cafe라는 호스트에 대한 IP 정보가 없음.

Web Service 미구동: DNS는 주소만 알려줄 뿐, 실제 웹사이트를 보여줄 Apache(httpd) 등의 웹 서버가 설정되지 않음.

해결 방법:

naver.com.db 파일에 cafe IN A 192.168.111.100 레코드 추가.

웹 서버 실습을 위해서는 별도의 httpd 패키지 설치 및 서비스 가동이 필요함을 인지함.

🔍 Issue 3: Thunderbird 클라이언트 연동 실패 (Invalid Configuration)
현상: 메일 클라이언트에서 계정 설정 시 "설정이 유효하지 않다" 또는 "인증 실패" 메시지 발생.

원인 분석:

ISP 자동 탐색 간섭: 썬더버드가 실제 상용 Daum 서버 설정을 가져와 실습용 서버와 충돌함.

보안 설정 오류: 실습 서버는 암호화(SSL/TLS)가 없는데, 클라이언트는 보안 연결을 시도함.

Sendmail 리스닝 제한: 기본 설정상 외부 접속(0.0.0.0)이 아닌 로컬(127.0.0.1)만 허용됨.

해결 방법 (추가 조치 필요):

수동 설정: 프로토콜을 POP3, 포트를 110/25, 보안을 None으로 강제 지정.

Sendmail 설정 수정: /etc/mail/sendmail.mc에서 Addr=127.0.0.1 부분을 0.0.0.0으로 수정 후 m4 컴파일.

Dovecot 설정 수정: /etc/dovecot/conf.d/10-auth.conf에서 disable_plaintext_auth = no로 평문 인증 허용.

3. 핵심 명령어 정리 (Cheatsheet)

작업 내용,명령어
DNS 설정 검사,named-checkzone [도메인] [존파일]
DNS 서비스 재시작,systemctl restart named
포트 가동 상태 확인,netstat -ntlp | grep :[포트번호]
DB 파일 생성 (Redirection),makemap hash /etc/mail/access < /etc/mail/access
메일 로그 실시간 모니터링,tail -f /var/log/maillog
방화벽 포트 허용,firewall-cmd --permanent --add-service=[service]

. 학습 소감 (Retrospective)
네트워크 인프라와 메일 프로토콜의 복잡한 유기적 관계를 이해하는 과정이었습니다. 
특히 **DNS(지도) -> SMTP(트럭) -> POP3(수신함)**으로 이어지는 흐름에서
어느 한 곳이라도 설정이 어긋나면 전체 서비스가 중단된다는 점을 실감했습니다. 
인프라 엔지니어에게 **로그 분석(Log Analysis)**과 
**네트워크 유효성 검사(nslookup, netstat)**가 얼마나 중요한지 배울 수 있는 유익한 실습이었습니다.
