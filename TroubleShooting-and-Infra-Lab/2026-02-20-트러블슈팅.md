1. 프로젝트 개요
목적: 원격 접속 서비스(Telnet, SSH) 구축 및 호스트(Windows 11) 간의 네트워크 통신 검증

환경: VMware Workstation, Rocky Linux (Server), Windows 11 (Client)

주요 도구: dnf, firewall-cmd, systemctl, PuTTY

2. 주요 트러블슈팅 사례
CASE 1. Telnet 서비스 접속 불가 및 방화벽 설정
문제 상황: 서버 측에서 서비스를 활성화했으나 외부 클라이언트에서 접속 실패.

원인 분석:

리눅스 기본 방화벽(firewalld)에서 23번 포트(Telnet) 미개방.

Windows 11 클라이언트 측에 'Telnet Client' 기능 비활성화.

해결 과정:

리눅스 방화벽 서비스 추가: firewall-cmd --add-service=telnet --permanent

윈도우 기능 추가: optionalfeatures를 통한 텔넷 클라이언트 활성화.

학습 포인트: 강사가 사용한 firewall-config(GUI) 방식과 달리 firewall-cmd(CLI)를 사용하여 정책을 수립하고 --reload를 통해 즉시 반영하는 실무 프로세스를 익힘.

CASE 2. SSH 실행 시 OpenSSL Version Mismatch 에러
문제 상황: SSH 서비스 시작 시 OpenSSL version mismatch 발생하며 데몬 실행 거부.

원인 분석: 패키지 간 의존성(Dependency) 불일치. SSH 패키지가 참조하는 라이브러리 버전과 실제 시스템 설치 버전이 상이함.

해결 과정:

시스템 패키지 전체 업데이트: dnf update -y

라이브러리 캐시 갱신: ldconfig

서비스 재시작: systemctl restart sshd

학습 포인트: 단순히 서비스를 재설치하는 것이 아니라, 라이브러리 의존성 트리를 정렬하여 시스템 정합성을 맞추는 고급 트러블슈팅 기법 체득.

3. 기술적 통찰 (Technical Insights)
사용자 계정 관리의 범용성
adduser 명령어를 통해 생성된 유저(teluser)는 리눅스 시스템 계정(/etc/passwd)으로 등록됨.

이는 접속 프로토콜(Telnet, SSH, FTP 등)에 관계없이 **동일한 인증 정보(PAM 구조)**를 공유함을 확인.

GUI vs CLI 방화벽 관리
GUI (firewall-config): 직관적이며 설정 오류가 적으나, 원격 서버나 텍스트 기반 환경(Headless Server)에서는 제약이 있음.

CLI (firewall-cmd): 초기 학습 난이도는 높으나 자동화 및 원격 관리에 필수적이며, 시스템의 작동 원리를 파악하기에 더 적합함.

[Troubleshooting] XRDP Service Access Issue & Log Analysis
1. 문제 상황 (Issue Description)
환경: Rocky Linux 9 (Server) / Windows 11 (Client)

현상: XRDP 서비스를 설치 및 활성화(active)했으나, 윈도우 원격 데스크톱 연결(MSTSC) 시도 시 "연결할 수 없음" 오류 발생 및 화면 출력 실패.

2. 로그 분석 (Log Inspection)
systemctl status xrdp 명령어를 통해 서비스 상태를 점검한 결과, 다음과 같은 에러 로그를 확인하였습니다.

Bash
# 주요 발생 에러 로그
[ERROR] SSL_write: I/O error
[ERROR] xrdp_sec_recv: xrdp_mcs_recv failed
[ERROR] xrdp_process_main_loop: libvnc_client_tmo failed
분석: 서비스 데몬은 정상 실행 중이나, 클라이언트와 서버 간의 SSL 핸드셰이크(보안 연결) 과정에서 데이터 패킷이 차단되거나 권한 문제로 세션이 중단됨을 파악.

3. 주요 디버깅 시도 (Debugging Steps)
① 방화벽 및 포트 점검
내용: RDP 표준 포트인 3389/tcp가 개방되어 있는지 확인.

조치:

Bash
firewall-cmd --add-port=3389/tcp --permanent
firewall-cmd --reload
② 보안 키 파일 권한 수정 (chown)
내용: XRDP가 암호화 통신을 위해 필요한 rsakeys.ini 파일에 접근하지 못하는 것으로 판단하여 소유권 변경.

조치:

chown root:xrdp /etc/xrdp/rsakeys.ini (주인을 root로, 그룹을 xrdp로 설정)

chmod 640 /etc/xrdp/rsakeys.ini (그룹 사용자에게 읽기 권한 부여)

③ 보안 정책(SELinux) 및 부팅 모드 변경
내용: 리눅스 커널 보안 모듈(SELinux)이 비정상적인 원격 화면 가로채기를 차단할 가능성 검토.

조치: setenforce 0을 통한 일시적 보안 해제 및 graphical.target 설정 확인.

4. 최종 분석 및 결론 (Conclusion)
미해결 원인: 시스템 전체 업데이트(dnf update) 과정에서 발생한 커널/라이브러리 정합성 이슈 또는 GUI 환경(GNOME)의 세션 충돌로 추정.

학습 성과:

로그 분석 능력: systemctl status의 에러 메시지를 통해 문제의 원인이 단순 서비스 미구동이 아닌 'SSL 통신 및 권한'에 있음을 기술적으로 파악함.

디버깅 프로세스: 문제 발생 시 재현 -> 로그 확인 -> 가설 수립 -> 조치로 이어지는 엔지니어링 사고방식을 실습함.

실무적 판단: 특정 서비스(GUI)에 매몰되기보다 서버 관리의 본질인 CLI(SSH) 환경 구축에 집중하여 인프라 가용성을 확보함.
