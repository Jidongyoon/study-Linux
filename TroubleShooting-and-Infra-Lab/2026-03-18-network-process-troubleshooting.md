## 🔍 2. 주요 트러블슈팅 사례 (Troubleshooting)

### ✅ 이슈 A: `localhost` 호출 시 루프백(`lo`) 인터페이스 미검출
| 현상 | 원인 | 해결 방법 |
| :--- | :--- | :--- |
| `hping3` 테스트 시 `lo` 패킷 0 | `localhost`가 외부 IP로 해석되어 `eth0` 경유 | `127.0.0.1` 주소를 사용하여 강제 루프백 통신 유도 |

### ✅ 이슈 B: 장고 프로세스 실종 및 `302 Found` 응답
| 현상 | 원인 | 해결 방법 |
| :--- | :--- | :--- |
| `curl` 결과 빈 화면 출력 | 서버가 로그인 페이지로 리다이렉트(`302`) 시킴 | `curl -I`로 헤더 확인 또는 `curl -L`로 경로 추적 |
| `ps`에서 장고 미검출 | `root` 계정 실행으로 인한 검색 누락 또는 프로세스명 불일치 | `ps -ef | grep python`으로 전체 파이썬 프로세스 전수 조사 |

### ✅ 이슈 C: `Address already in use` (Errno 98)
| 현상 | 원인 | 해결 방법 |
| :--- | :--- | :--- |
| 서버 실행 시 포트 충돌 에러 | 종료되지 않은 `root` 권한 프로세스가 8000 포트 선점 | `sudo fuser -k 8000/tcp` 명령으로 포트 점유 강제 해제 |

## 💡 오늘의 핵심 레슨 (Key Takeaways)

1. **포트(Port)는 절대 거짓말하지 않는다.**
   - 프로세스가 안 보여도 포트 충돌이 나면 반드시 어딘가(특히 `root` 계정)에 범인이 숨어 있다.
2. **응답 코드(HTTP Status)를 먼저 확인하자.**
   - 데이터가 안 나올 땐 `curl -I`를 통해 서버가 나에게 리다이렉트(`301/302`)를 던지는지 확인해야 한다.
3. **인터페이스(Interface)의 경로 이해.**
   - `localhost`와 `127.0.0.1`은 시스템 설정에 따라 서로 다른 인터페이스를 탈 수 있다.
