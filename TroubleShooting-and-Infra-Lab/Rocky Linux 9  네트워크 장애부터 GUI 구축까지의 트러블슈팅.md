# 🌐 리눅스 네트워크 장애 분석 및 GUI 환경 구축 보고서 (2026-01-31)

본 문서는 Rocky Linux 9 실습 과정에서 겪은 네트워크 장애 해결부터 GUI 구축, 그리고 최종 시스템 백업까지의 모든 과정을 단계별로 기록한 기술 문서입니다.

---

## 1. 🔍 단계별 트러블슈팅 로직

### [Step 1] 장치 활성화 (Network Interface)
* **현상**: IP 할당이 안 되고 외부 통신이 전혀 불가능함.
* **해결**: `nmcli device connect [장치명]`
* **교훈**: 하드웨어(랜카드)가 존재해도 OS 레벨에서 활성화(Up)되지 않으면 통로 자체가 형성되지 않는다.

### [Step 2] DNS 설정 및 외부 연결 (Connectivity)
* **현상**: `8.8.8.8`(IP)로는 핑이 가는데, `google.com`(도메인)으로는 가지 않음.
* **해결**: `/etc/resolv.conf`에 `nameserver 8.8.8.8` 등록.
* **교훈**: 인터넷 통로가 뚫려 있어도, 별명을 주소로 바꿔줄 **'비서(DNS)'**가 없으면 서비스 접속이 불가능하다.

---

## 2. 🧠 DNS에 대한 오해와 진실

### ❓ 내가 가졌던 오해
> "가상머신을 설치하면 각 머신마다 고유의 DNS 서버가 자동으로 할당되어 돌아가는 것 아닌가?"

### ✅ 바로잡은 개념
1. **DNS는 서버가 아니라 '연락처'다**: 가상머신 내부에 DNS 서버가 생기는 것이 아니라, 외부에 있는 **유능한 안내원(구글 8.8.8.8 등)에게 연락하는 방법**을 배우는 과정이다.
2. **8.8.8.8을 쓰는 이유**: 내 네트워크의 안내원이 불안정할 때, 세계에서 가장 확실한 구글 안내원 번호를 직접 등록하여 통신을 보장하기 위함이다.

## 3. 🛠️ GUI(Workstation) 구축 및 장애 해결 ("Oh no!" 에러)

### 🔴 장애 현상
- GUI 패키지 설치 후 진입 시, 슬픈 아이콘과 함께 **"Oh no! Something has gone wrong."** 메시지 출력 후 정지.

### 🔍 원인 분석 및 해결
1. **의존성 결함**: 네트워크 문제로 약 1,000개의 패키지 중 일부가 누락됨 → `dnf groupinstall "Workstation"` 재실행으로 완수.
2. **그래픽 가속 충돌**: VMware의 3D 가속 기능과 GNOME 데스크톱 간의 충돌 → **VMware 설정에서 'Accelerate 3D graphics' 해제**.
3. **비상구 활용**: 화면 멈춤 시 **TTY(Ctrl+Alt+F3)**로 진입하여 터미널에서 시스템 복구 진행.

## 💡 핵심 명령어 및 시스템 제어 (systemd)

| 명령어 | 의미 | 비고 |
| :--- | :--- | :--- |
| `systemctl isolate graphical.target` | **즉시 전환** | 재부팅 없이 즉시 GUI 모드로 무대 세트 교체 |
| `systemctl set-default graphical.target` | **영구 고정** | 다음 부팅 시에도 무조건 GUI로 시작되도록 저장 |
| `systemctl get-default` | **상태 확인** | 현재 시스템의 기본 부팅 모드(Target) 확인 |
| `startx` | **수동 호출** | 텍스트 모드에서 그래픽 환경을 수동으로 실행 |

## 📦 저장소 관리 및 최종 백업

### 1) Vault vs Pub
- **Vault (금고)**: 은퇴한 OS 버전 보관소.
- **Pub (매장)**: 현역 버전 보관소. 현역인 Rocky 9을 Vault에서 찾으려 했던 경로 오류를 수정하여 해결.

### 2) 시스템 스냅샷 (Snapshot)
- **작업**: 모든 설정 완료 후 **`GUI_Setup_Complete`** 스냅샷 생성.
- **의의**: 향후 실습 중 시스템이 붕괴되어도 10초 만에 오늘의 완벽한 상태로 복구 가능한 '세이브 포인트' 확보.

## 🏁 최종 결론
트러블슈팅은 **'장치(Interface) -> 안내원(DNS) -> 보관소(Repo) -> 피부(GUI) -> 문지기(Port)'**로 이어지는 연결 고리를 하나씩 검증하는 과정이다. 8시간의 사투를 통해 리눅스의 논리적 구조를 깊이 이해하게 되었다.
