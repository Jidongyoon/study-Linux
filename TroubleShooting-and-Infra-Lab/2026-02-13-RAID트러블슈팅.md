# 🛠️ Linux Storage & RAID Troubleshooting Report

오늘 실습하며 겪은 주요 에러 상황과 해결 방안, 그리고 핵심 개념을 정리한 문서입니다.

## 1. `mdadm.conf` 설정 파일 불일치
- **현상**: 강사 화면에는 있는 `name=...` 문구가 내 설정에는 없음.
- **원인**: 최신 `mdadm` 버전은 호스트 이름(`localhost`) 의존성을 줄이기 위해 이를 생략하고 **UUID** 위주로 정보를 생성함.
- **해결**: 해당 문구가 없어도 RAID 동작에는 지장이 없음. 오히려 시스템 이름 변경 시 발생할 수 있는 인식 오류를 방지할 수 있어 더 깔끔한 상태임.

---

## 2. 부팅 실패와 응급 모드(Emergency Mode)
- **현상**: `/etc/fstab` 수정 후 재부팅 시 시스템 접속 불가(응급 모드).
- **원인**: `fstab` 설정값이 시스템(systemd)에 즉시 반영되지 않았거나 오타가 있는 상태에서 부팅 시도.
- **해결**:
  1. `systemctl daemon-reload`: 수정된 `fstab` 내용을 시스템에 즉시 반영.
  2. `mount -a`: 재부팅 전 미리 마운트 테스트를 진행하여 에러 유무 확인.
- **핵심**: `fstab` 수정 후 **데몬 리로드**와 **마운트 테스트**는 필수 루틴임.

---

## 3. `cp` 명령어: Target is not a directory
- **현상**: 와일드카드(`*`) 복사 시 `cp: target is not a directory` 에러 발생.
- **원인**: 복사하려는 원본 파일은 여러 개인데, 목적지 이름이 디렉토리(폴더)로 존재하지 않아 리눅스가 파일 하나에 여러 개를 합칠 수 없다며 거부함.
- **해결**: `mkdir` 명령어로 목적지 디렉토리를 먼저 생성한 후 복사 진행.
- **교훈**: 강사가 성공한 이유는 화면 밖에서 이미 디렉토리를 만들어 두었기 때문임.

---

## 4. 장치 점유(Device or resource busy) 오류
- **현상**: RAID 생성/수정/삭제 시 "Busy" 메시지와 함께 명령 거부.
- **원인**: 대상 장치가 이미 마운트되어 있거나, 커널이 이전 레이드 메타데이터(Superblock)를 잡고 있기 때문.
- **해결 프로세스 (해방 3단계)**:
  1. `umount [장치명]`: 마운트 해제.
  2. `mdadm --stop /dev/mdX`: 실행 중인 논리 어레이 정지.
  3. `mdadm --zero-superblock /dev/sdX1`: 디스크의 레이드 흔적 완전 삭제.
- **핵심**: `lsblk`를 쳐서 장치 하위에 아무런 연결(가지)이 없을 때까지 풀어줘야 함.

---

## 5. 리눅스 파일 유형과 블록 장치(`b`)
- `d`: 디렉토리 (Directory)
- `-`: 일반 파일 (Regular File)
- `l`: 심볼릭 링크 (Link)
- **`b`: 블록 장치 (Block Device)**: 하드디스크, RAID 등 저장 매체.
- **특징**: 데이터를 블록 단위로 처리하며, 리눅스에서는 하드웨어도 파일 형태로 관리됨.

---

## 6. 주요 명령어 요약

| 명령어 | 용도 | 비고 |
| :--- | :--- | :--- |
| `lsblk` | 전체 디스크 구조 확인 | 마운트 계층 파악의 1순위 |
| `df -h` | 마운트된 용량 확인 | `-h` 옵션으로 기가(G) 단위 확인 |
| `cat /proc/mdstat` | RAID 가동 상태 확인 | 현재 활동 중인 레이드 멤버 확인 |
| `grep` | 특정 키워드 필터링 | `df -h | grep md0` 처럼 사용 |
| `mdadm --examine` | 디스크 메타데이터 확인 | 과거 레이드 흔적 추적 |

---

### 💡 최종 회고
우분투 경험 덕분에 전체적인 흐름 파악이 수월했으나, 실제 디스크 결함 허용(Fault Tolerance) 실습에서 발생하는 **장치 점유 문제**는 실무적인 트러블슈팅 능력을 요구함. 에러 메시지를 단순히 무시하지 않고 **'장치가 바쁜 이유'**를 유추하여 `umount`와 `zero-superblock`으로 해결하는 과정이 이번 실습의 가장 큰 수확임.
