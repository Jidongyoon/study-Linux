# 🐧 [Day 1] AI 리눅스 서버관리 기초: 시스템의 뿌리 이해하기

> **학습 목표**: 명령어 암기가 아닌, 리눅스 커널의 자원 관리 원리와 엔지니어의 탑다운(Top-Down) 사고방식 습득.

---

## 🏗️ 1. 리눅스 시스템 구조 (The Big Picture)

리눅스는 거대한 **C언어 프로그램**(약 10만~20만 개의 함수)이며, 크게 두 갈래의 관리 영역으로 나뉩니다.

| 분류 | 관리 대상 | 핵심 구성 요소 |
| :--- | :--- | :--- |
| **애플리케이션 계층** | 프로세스 관리 | 웹 서버, DB, 브라우저, 각종 앱 |
| **하드웨어 계층** | 자원(Resource) 관리 | **CPU, Memory, Disk, Network** |

### 🧠 코어 동작 메커니즘 (무한 반복)
사용자 눈에 보이지 않지만, 커널은 아래 두 가지 이벤트를 끊임없이 처리하며 시스템을 유지합니다.
- **인터럽트(Interrupt)**: 하드웨어(키보드, 타이머, NIC)가 CPU에 보내는 신호.
- **예외처리(Exception)**: 소프트웨어가 자원을 요청(System Call)하거나 에러가 발생했을 때 처리.

---

## 💻 2. 하드웨어 자원 관리 (The 4 Pillars)

서버 스캐닝의 핵심은 아래 4대 자원의 상태를 논리적으로 파악하는 것입니다.

| 자원 | 확인 명령어 | 엔지니어의 관점 |
| :--- | :--- | :--- |
| **CPU** | `lscpu`, `top` | 연산 부하 및 인터럽트 처리량 확인 |
| **Memory** | `free -m`, `top` | 가상 메모리와 물리 메모리의 매핑 상태 확인 |
| **Disk** | `df -h`, `lsblk` | 저장 공간의 여유 및 파티션 구조 확인 |
| **Network** | `netstat -lnp` | 열려 있는 포트와 프로세스 연결 상태 확인 |

---

## 🧠 3. 메모리 관리의 심화 개념 (VIRT vs RSS)

리눅스는 보안과 효율을 위해 모든 프로세스에게 **가상 메모리**를 부여합니다. 엔지니어는 `top` 명령어에서 다음 두 수치를 구분할 줄 알아야 합니다.

| 개념 | 풀네임 | 의미 | 비유 |
| :--- | :--- | :--- | :--- |
| **VIRT (VSZ)** | Virtual Memory Size | 프로세스가 커널에 예약한 가상 메모리 총량 | **식당 예약석** (자리는 맡았지만 아직 안 옴) |
| **RSS (RES)** | Resident Set Size | **실제 물리 RAM**에 올라와 있는 사용량 | **실제 손님** (진짜 RAM을 차지하고 있는 인원) |

> **💡 핵심 요점**: 서버 메모리 부족(OOM) 이슈를 분석할 때는 예약량(VIRT)이 아닌 **실제 점유량(RSS)**을 추적해야 한다.

---

## 🛠️ 4. 엔지니어의 서버 스캐닝 논리 (Top-Down)

어떤 리눅스 환경(물리 서버, VM, 도커)을 만나도 당황하지 않는 3단계 스캔법:

1. **App 스캔**: `ps -ef`로 현재 어떤 서비스가 돌고 있는지 확인.
2. **Core 스캔**: `top`, `vmstat`으로 시스템 부하와 이벤트(인터럽트) 상태 확인.
3. **HW 스캔**: `df`, `free`로 물리적 자원의 한계치 도달 여부 확인.

---

## 🌟 오늘의 회고 (Insight)
- 리눅스는 단순한 도구가 아니라, 자원을 배분하는 **정교한 관리자**이다.
- 도커와 쿠버네티스도 결국 리눅스 커널의 **프로세스 격리 및 자원 관리** 기능을 확장한 것이다.
- **"로그와 수치를 믿고, 인과관계를 추적하는 것"**이 엔지니어 사고의 시작이다.
