# 📝 Linux Kernel Memory Management & Watermark Mechanism

오늘 공부한 리눅스 커널의 핵심 메모리 관리 이론과 실습 내용을 정리한 문서입니다.

---

## 💡 1. 가상 메모리와 물리 메모리 (VSZ vs RSS)
리눅스는 프로세스가 시작될 때 실제 물리 RAM을 미리 할당하지 않는 **지연 할당(후매핑, Lazy Allocation)** 방식을 사용합니다.
* **깡통 매핑 테이블:** 가상 주소 공간(VMA)만 예약 장부(`mm_struct`)에 기록하고 물리 주소(PA) 매핑은 비워둡니다.
* **핵심 지표:**
  * **VSZ (Virtual Size):** 예약된 가상 메모리 주소 영역의 총합.
  * **RSS (Resident Set Size):** 실제 물리 RAM에 매핑되어 공간을 차지한 양.
  * **USS / PSS:** 독점 메모리 크기 및 공유 메모리 지분(1/N)을 반영한 실질 지표.

## ⚙️ 2. `mmap()`과 메모리의 두 가지 속성
`malloc()`은 내부적으로 커널 시스템 콜 `mmap()`을 호출하여 대량의 가상 주소 공간(VMA)을 할당받습니다.
1. **페이지 캐시 (Page Cache):** 하드디스크의 특정 **파일과 연결**된 메모리 영역.
2. **익명 페이지 (Anonymous Page):** 고향 파일이 없는 순수한 **스택(Stack) 및 힙(Heap) 영역**.

## 🏃‍♂️ 3. 메모리 워터마크와 `kswapd` 청소 메커니즘
커널은 물리 RAM의 여유 공간을 실시간으로 감시하기 위해 3가지 한계선(Watermark)을 운영합니다.

* **High 선 (안전지대):** 메모리가 충분하여 청소부가 잠을 자는 상태 (`kswapd0 sleep`).
* **Low 선 (경고지대):** 여유 메모리가 이 선 밑으로 떨어지면 **`kswapd0` 데몬이 깨어나 백그라운드 청소(페이지 회수)**를 시작.
  * 최근에 안 쓴 방(`LRU list` 기준)을 추려내어 공간 확보.
  * 파일 기반은 메모리에서 삭제 (**`page-out`**), 익명 페이지(힙)는 디스크 스왑 구역으로 백업 (**`swap-out`**).

## 🚨 4. 최후의 비상사태: `Direct Reclaim` (직접 회수)
* **발생 조건:** 메모리 요청 폭주로 여유 공간이 **`Min` 워터마크 선**마저 뚫고 내려갔을 때 발생합니다.
* **작동 방식:** 백그라운드 청소부 혼자 감당이 안 되므로, **메모리를 요청한 프로세스들이 직접 동기적으로 기존 메모리를 스왑 아웃**시킵니다.
* **영향:** 프로세스가 일시 정지(Block)되므로 서버 전체에 **극심한 랙(병목 현상)**이 발생하게 됩니다.

## 🛠️ 5. 실무 명령어 및 모니터링
* `/proc/zoneinfo` 조회를 통해 시스템 내부의 실제 워터마크 수치(Page 단위) 확인 가능.

```bash
# 메모리 존(Zone) 정보 및 워터마크(min, low, high) 수치 확인
$ cat /proc/zoneinfo | grep -A 7 DMA32

# 특정 프로세스의 실시간 메모리 상태(Vn 지표) 추적
$ watch -n 0.1 'cat /proc/[PID]/status | grep Vm'
