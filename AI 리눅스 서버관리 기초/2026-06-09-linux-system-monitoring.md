## 1. 프로세스 수명 주기와 좀비 프로세스 (Zombie Process)

### 📌 핵심 개념 요약
* **부모의 책무:** 자식 프로세스(`fork()`)가 종료되었을 때, 부모 프로세스는 반드시 `wait()` 시스템 콜을 호출하여 자식의 종료 상태(Exit Status)를 읽고 시스템 자원을 해제(`free`)해야 합니다.
* **좀비 프로세스(S 상태: Z) 발생 원인:** 자식이 종료되었음에도 부모가 `wait()`를 호출하지 않고 다른 작업(예: `sleep`)을 하느라 자원의 흔적을 정리하지 않을 때 발생합니다.
* **커널의 자동 고아 구제 (Orphan Reaping):** 부모 프로세스가 자식보다 먼저 완전히 종료되면, 고아가 된 자식 프로세스는 **`init` 프로세스(`systemd`, PID 1)**가 자동으로 입양(`Adopt`)합니다. 이후 `init`이 `wait()` 시스템 콜을 대신 호출하여 좀비 상태가 되는 것을 완벽하게 방지합니다.

### 💡 데몬/웹 서버(Nginx 등)가 좀비를 남기지 않는 구조적 이유
1. **시그널 핸들러(`SIGCHLD`):** 자식이 죽는 순간 부모에게 `SIGCHLD` 신호(삐삐 알림)가 가며, 부모는 비동기적으로 즉시 `wait()`를 처리하여 성불시킵니다.
2. **멀티 스레딩 인터페이스:** `fork()` 대신 메모리 공간을 공유하는 스레드(`Thread`)를 주로 사용하여 자식 찌꺼기가 남지 않게 설계합니다.
3. **Graceful Restart (`systemctl reload`):** 서비스 중단 없이 주기적으로 자식 프로세스들을 새 장부로 세대교체하여 누수 자원을 자동 청소합니다.

## 2. 인터럽트 지연 처리 구조 (Top Half / Bottom Half)

리눅스 커널은 **이벤트 핸들링(인터럽트) 방식**으로 동작합니다. 하드웨어 신호 처리 중에는 다른 인터럽트가 차단되므로, 시스템 응답성(Response Time)을 극대화하기 위해 처리를 이단계로 쪼갭니다.

* **Top Half (TH 함수):** 랜카드/디스크 신호를 받아 장부에 최소한의 기록(접수 도장)만 남기고 즉시 인터럽트 제한을 해제합니다. (빛의 속도로 종료)
* **Bottom Half (BH 함수):** 무거운 데이터 분석 및 후속 처리를 담당합니다. 이 처리를 미루지 않고 문앞에서 다 처리하면 시스템이 일시적으로 얼어버리는 대참사(네트워크 패킷 유실, 키보드 먹통 등)가 발생합니다.

---

## 3. 워크큐(Workqueue)와 kworker의 정체

* **워크큐 (Workqueue):** Top Half 단계에서 미뤄둔 무거운 후속 작업(BH)들을 비동기적으로 쌓아두는 **'커널 전용 대기 행렬(보관함)'**입니다.
* **kworker (Kernel Worker):** 워크큐에 쌓인 일감들을 백그라운드에서 하나씩 꺼내어 처리하는 **'리눅스 커널 전용 전담 일꾼 스레드'**입니다.
* **구조적 핵심:** `kworker`는 일반 프로세스와 같은 정식 스레드 형태이므로, 디스크 I/O 작업처럼 대기 시간이 필요한 최고의 순간에 **안전하게 잠을 자거나 대기(`Sleep/Block`) 상태로 들어갔다 깨어날 수 있습니다** (일반 인터럽트 컨텍스트 내에서는 불가능).

## 4. `top` %Cpu(s) 라인 완벽 분석

> `%Cpu(s):  8.5 us,  2.8 sy,  0.0 ni, 88.4 id,  0.0 wa,  0.0 hi,  0.2 si,  0.0 st`

* **`us` (User):** 사용자가 켠 일반 프로그램(크롬, UI, 애플리케이션 등)이 CPU를 점유한 비율입니다.
* **`sy` (System):** 리눅스 커널 및 운영체제 자체 관리 작업(`fork` 제어 등)에 할당된 비율입니다.
* **`id` (Idle):** CPU가 아무것도 안 하고 쉬고 있는 널널한 여유 능력치입니다.
* **`wa` (IO wait):** 디스크 읽기/쓰기가 끝나기를 기다리며 CPU가 손 놓고 멈춰 있는 답답한 시간입니다. 이 수치가 높으면 디스크 병목을 의심해야 합니다.
* **`hi` (Hardware Interrupt):** 랜카드, 물리 장치의 실시간 신호 접수에 소요된 시간입니다.
* **`si` (Software Interrupt):** 무거운 후속 연산에 쓰인 시간입니다. **디도스(DDoS) 공격이나 네트워크 트래픽 폭주 시, 패킷 포장을 뜯고 분석하느라 이 `si` 수치가 폭발적으로 상승합니다.**

## 5. `top` Memory (RAM / SWAP) 장부 분석

> `KiB Mem : 16165704 total,   280716 free,  8692136 used,  7192852 buff/cache`  
> `KiB Swap:  2097148 total,  2094076 free,     3072 used.  3635004 avail Mem`

### 📦 KiB Mem (실제 물리 RAM 창고)
* **`total`:** 시스템에 장착된 총 물리 메모리 양입니다.
* **`free`:** 완전하게 텅텅 비어 있는 순수 빈 공간입니다. 리눅스는 메모리를 놀리지 않으므로 평소엔 이 값이 매우 작게 내려갑니다.
* **`used`:** 프로그램들이 실행을 위해 반드시 점유하고 있는 실질적 필수 공간입니다.
* **`buff/cache`:** 디스크에서 자주 꺼내는 데이터를 속도가 빠른 RAM에 임시 저장해 둔 공간입니다. 새 프로그램이 자리를 요구하면 즉시 양보되므로 공간이 부족하다고 판단하면 안 됩니다.

### 🛒 KiB Swap & 가상 메모리
* **`Swap`:** 물리 RAM이 부족할 때를 대비해 하드디스크/SSD 공간의 일부를 빌려 쓰는 비상금 창고입니다. `Swap used`가 급증하면 디스크 스왑 병목으로 인해 시스템이 크게 버벅댑니다.
* **`avail Mem` (★가장 중요):** `free` 공간에 `buff/cache`에서 즉시 반환 가능한 용량까지 영혼까지 끌어모은 **'실질적인 즉시 사용 가능 여유 메모리'** 성적표입니다. 인프라 모니터링 시 이 수치를 최우선으로 확인합니다.
