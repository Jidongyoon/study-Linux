[Real Linux] 리눅스 커널 자원 관리 및 웹 서비스 실습 (2026-03-12)
핵심 요약: 리눅스 커널이 CPU/메모리 자원을 어떻게 배분하는지 이해하고, Nginx와 Node.js를 연동하여 실제 웹 서비스의 동작 원리를 파악한다.

1. 리눅스 커널의 프로세스 및 자원 관리
커널은 하드웨어 자원을 효율적으로 사용하기 위해 task_struct라는 일꾼 관리 시스템을 운용합니다.

🏃 CPU 스케줄링 (Runqueue vs Waitqueue)
Runqueue (실행 큐): CPU 코어마다 존재하며, 지금 당장 CPU를 써서 일할 준비가 된 task_struct들이 서는 줄입니다.

Waitqueue (대기 큐): I/O 요청(디스크, 네트워크 등) 후 응답을 기다리며 잠(Sleep)에 든 상태의 프로세스들이 머무는 곳입니다.

🏗️ 메모리 구조 (mm_struct)
멀티 쓰레드: 하나의 메인 프로세스 내에서 여러 쓰레드가 돌아가며, 이들은 하나의 mm_struct(메모리 설계도)를 공유합니다.

멀티 프로세스: 각 프로세스가 독립적으로 돌아가며, 프로세스 개수만큼 개별적인 **mm_struct**를 가집니다.

2. 웹 서버(Nginx)와 WAS(Node.js)의 구조
웹 서비스는 성능과 기능 구현을 위해 역할을 분담합니다.

웹 서버 (Nginx, httpd): C언어로 작성된 빠르고 단단한 프로그램으로, 주로 HTTP 통신 처리와 정적 데이터 전달을 담당하는 '네트워크 장비'와 같은 역할을 합니다.

WAS (Node.js, Spring, Django): Java, Python, JS 등을 통해 회원가입, 로그인, 결제 등 실제 서비스 기능을 구현하는 '애플리케이션 서버'입니다.

3. 리눅스 환경에서의 웹 서비스 구축 실습
Rocky-8 환경에서 Node.js 서버를 구동하고 Nginx와 연동하는 실습을 진행했습니다.

🛠️ 주요 실습 명령어
파일 작성 및 확인:

$ nano app.js: Node.js 소스 코드 작성

$ cat app.js: 코드 내용 확인

서버 실행:

$ node app.js: 3000번 포트에서 웹 서비스 구동

포트 포워딩 연동:

사용자가 접속하는 80번 포트를 내부의 3000번 포트로 연동하여 Nginx와 Node.js를 연결합니다.

🔍 실무 트러블슈팅 3단계 (생활화)
문제가 발생했을 때 범위를 좁혀가는 엔지니어의 핵심 절차입니다.

프로세스 생존 확인: $ ps -ef | grep node

일꾼(task_struct)이 메모리에 실제로 떠 있는지 확인합니다.

네트워크 포트 확인: $ sudo netstat -tplan | grep 3000

해당 프로세스가 지정된 포트(3000)를 제대로 열고(LISTEN) 있는지 확인합니다.

동작 확인: $ curl http://localhost:3000

로컬에서 직접 요청을 보내 응답(예: "Hello, World!")이 오는지 최종 확인합니다.
