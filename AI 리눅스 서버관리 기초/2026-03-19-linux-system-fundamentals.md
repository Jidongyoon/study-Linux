## 1. ⚖️ 리소스 관리: ulimit (Open Files)
서버가 동시에 수용할 수 있는 '연결의 수'를 결정하는 핵심 설정입니다.

* **문제 상황**: 부하 테스트 중 `socket: Too many open files` 에러 발생.
* **원인**: 리눅스는 소켓을 파일로 취급하며, 기본 한도가 **1,024**로 제한되어 있음.
* **해결 (현업 기준)**: 트래픽 감당을 위해 보통 **65,535**개 이상으로 상향 조정함.
* **주요 명령어**:
    * `ulimit -a`: 전체 커널 제한 사항 확인
    * `ulimit -n 65535`: 오픈 파일 한도 즉시 상향 (임시)
    * `/etc/security/limits.conf`: 영구 설정을 위한 설정 파일

## 🌳 2. 프로세스 계층 구조: PID & PPID
리눅스 내의 모든 실행 주체는 부모-자식 관계의 가계도를 가집니다.

* **PID (Process ID)**: 프로세스 고유 번호.
* **PPID (Parent Process ID)**: 나를 실행시킨 부모 프로세스의 번호.
* **PID 1 (systemd/init)**: 부팅 시 커널이 가장 먼저 실행하는 **'모든 프로세스의 조상'**.
* **진단 기술**: `ps -ef` 명령어를 통해 특정 서비스(예: nginx)가 어떤 경로로 실행되었는지 족보를 추적하여 장애 원인을 파악함.

## 📦 3. 패키지 유통 시스템: dnf/yum & Metadata
리눅스에서 소프트웨어를 관리하는 체계적인 아키텍처입니다.

* **High-Level (dnf/apt)**: 인터넷 저장소(Repository)에서 패키지를 찾아 **의존성(Dependency)**을 해결하고 설치하는 배달 앱 역할.
* **Low-Level (rpm/dpkg)**: 실제 패키지 파일을 시스템에 설치하는 요리사 역할.
* **Metadata Cache**: 빠른 검색을 위해 로컬(`/var/cache/`)에 저장해둔 패키지 리스트(전단지).
* **트러블슈팅**:
    * `yum clean all`: 낡은 캐시 정보를 삭제.
    * `yum makecache`: "Repodata is over 2 weeks old" 에러 발생 시 최신 정보를 인터넷에서 다시 받아와 지도(캐시)를 갱신함.

## 🚀 인프라 확장 전략: Scale-up vs Scale-out
트래픽 폭주 시 서버가 대응하는 두 가지 필살기입니다.

1.  **Scale-up (수직 확장)**: 서버 한 대의 CPU/RAM 성능을 물리적으로 강화. 설정이 쉽지만 한계가 명확함.
2.  **Scale-out (수평 확장)**: 여러 대의 서버를 병렬로 연결. 로드 밸런싱을 통해 무한 확장이 가능하며 한 대가 죽어도 서비스가 유지되는 '고가용성' 확보 가능.

## 🩺 실시간 모니터링 및 진단 도구
* **bmon**: 실시간 네트워크 트래픽(RX/TX) 모니터링. 그래프가 평평해지면 대역폭 한계 도달 신호.
* **netstat -tplan**: 현재 열려 있는 포트와 연결된 IP 상태 확인.
* **curl -v**: 서버와의 통신 과정을 상세히 출력하여 네트워크 구간 문제 진단.
